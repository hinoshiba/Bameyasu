# Security Policy

## Supported versions

Only the latest App Store release and the current `main` branch receive security fixes.

## Reporting a vulnerability

Do not open a public issue for a vulnerability or privacy leak. Email [support@hinoshiba.com](mailto:support@hinoshiba.com) with the affected version, device/iOS version, reproduction steps, impact, and a minimal proof of concept without real user data.

The maintainer should acknowledge reports within seven days, provide status at least every 14 days while investigating, coordinate disclosure, and credit the reporter if requested and appropriate.

Never send private keys, signing identities, certificate/private-key bundles, provisioning profiles, App Store Connect keys, Keychains, or other credentials to this project through an issue, pull request, email, attachment, or alternate transfer channel. If such material is exposed, do not resend its contents; report only its type, path, and affected commit or job so the maintainer can revoke or rotate it and remove it from history.

Do not attach captured images, audio, personal data, or other sensitive diagnostic material to a public issue or initial email. The maintainer may arrange a safer transfer method for non-credential diagnostic material only. Signing and credential material is governed by the [code-signing policy](docs/CODE_SIGNING.md) and is never accepted for transfer to the project.
